Where I start

The most interesting line in AI right now

Attention(Q, K, V) = softmax ( QK⊤√dk ) V
Q
What I am looking for right now. The question.
K
What each piece of context claims to be about.
QK⊤
How well every key matches the question, all at once.
√dk
A quiet fix. Without it, scores grow with dimension and softmax collapses onto one token.
V
What each piece actually says, blended by weight.

Every frontier model since 2017 runs on this line, and what it encodes is a learned answer to one question: what matters right now?

The part I find most interesting is that models did not get better by reading more. They got better by weighting better. The softmax is a budget. Every bit of attention spent on an irrelevant token is attention taken from the one that mattered.

Most of my work is that same question one level up, where I build the weighting myself. For Krishi Mitra it was: out of a forty-page government scheme document, which paragraph answers this farmer? At Allegis it was: out of hundreds of stored procedures, which one actually broke? Retrieval is attention you engineer by hand. Get the weighting wrong and the model does not stop. It answers confidently from the wrong context.

How I got here

Four problems, one thread

2023 – 2025
Pune, India

Krishi Mitra: AI that speaks the farmer's language

The information farmers need already exists online: government schemes, subsidies, crop and irrigation guidance. It is scattered, written in bureaucratic English, and hard to trust. So most farmers rely on word of mouth instead.

With three teammates I built a conversational assistant around a fine-tuned LLaMA 3.2 3B, quantized to run locally through llama.cpp, with a RAG pipeline that pulls live answers from trusted agricultural and government sources and replies in Hindi, Marathi or English. It ran on cheap hardware on purpose. The people it was for do not have GPUs.

Fortytwo Labs

Finding what does not belong

My first production ML work was security. Autoencoders learned what normal login behaviour looks like, and a hybrid KMeans and DBSCAN layer flagged the rest. The models fed a Drools rule engine that scored risk automatically. It was the first time I saw a model change what people spend their day on.

2025 – 2026
University of Maryland

Breaking other people's research to learn where ML quietly fails

Under Prof. William Regli I helped run a reproducibility audit of the neuro-symbolic AI literature. We rebuilt published codebases on the Zaratan HPC cluster and checked whether the numbers held. Often they did not, for boring reasons: a hyperparameter missing from the paper, an evaluation split that quietly changed, an environment nobody pinned.

That taught me to distrust a system that cannot show how it was measured. Everything I build now ships with its eval.

5,497 records→1,304 eligible→85 reproduced→arXiv + under review at IEEE TNNLS
Summer 2026
Allegis Global Solutions

Weeks to days: an agent that debugs the pipeline

When a pipeline feeding AGS's Acumen workforce platform broke, someone had to trace it by hand through layer after layer of stored procedures. Sometimes that took weeks. I built a multi-agent triage system on Snowflake Cortex that does the tracing, checks the data, finds precedent, and proposes the fix for a human to approve. It learned new failure patterns from a YAML instruction layer, without retraining.

It is the same problem as the farmers, at enterprise scale: find the one thing that matters in a lot of context, then be honest about how sure you are. You can run a reconstruction of it just below.

~65% faster root causeweeks → daysfix proposals: hours → minutes

Building in public

Making the pattern reusable

Two open-source builds that generalise what Allegis taught me. A LangGraph incident triage graph with an MCP server and an eval suite that gates CI. Its noisy test set showed rule-based classification gets fooled about one time in five, which is exactly why the human gate stays. It now also has an LLM investigator that walks the graph itself, cross-checked by the rules. And Keel, the runtime where an approved fix actually happens: the agent applying it can do nothing unapproved, nothing twice and nothing skipped, even through a crash.

Both agents on real models

One agent can think, the other can act.

The diagnoser is the triage project's LLM investigator: five read-only tools, so its worst case is a wrong answer, never a wrong action. A person approves its plan. The fixer then writes to the warehouse inside Keel, which refuses anything else and logs why. On 40 labelled incidents, half held out, on a laptop RTX 4060, the model found the root cause 28 times; the rule-based tracer found all 40, which is why it cross-checks the model and a person approves.

Where I started: anomaly detection

A login, scored while you watch

Before agents, I built risk-based authentication at Fortytwo Labs. An autoencoder learns what one person's normal logins look like and rebuilds each new login through a 4-number bottleneck. Normal behaviour comes back almost unchanged. An attacker's does not, and the rebuild error becomes the risk score. Try an attack.

The graph decides what happens next. Keel decides what an agent can do at all: the loop, the context budget, the sandbox, the run log. An approved plan becomes an envelope the agent cannot leave or under-fill. Every tool call is logged as started, dispatched, then done, so a crashed run resumes without repeating a side effect. It runs two Qwen3 8B agents, a read-only diagnoser from the triage project and a fixer, and tunes its own recovery rules behind a safety gate.
